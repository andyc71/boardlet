# Safe production upgrade path

The development app IDs are `com.brightblue.boardlet.development` and `com.brightblue.boardlet.plus.development`. They do not have access to either production sandbox. Side-by-side testing uses read-only copies of legacy folders selected in Settings, or self-contained Boardlet JSON backups. Do not install these builds using production IDs or delete existing apps to test migration.

Before a release, resolve the documented Dynavox dependency asset failure, configure/test the optional application-owned AI service, and finish physical-device audio/camera and Duo coverage. Use the existing signing and entitlement configuration only after reviewing it; the new project deliberately has no inherited backend credentials, analytics or build-number scripts.

For an eventual in-place update, Standard maps to `com.brightblue.EasyPECS`; Plus maps to `com.brightblue.EasyPECSPlus`. The old app must remain installed. Updating with the same identity retains its Documents sandbox. New storage is under Documents/Boardlet and does not overwrite old board folders. The migration adapter can import Documents as a whole. Importing is a staged process: read metadata, validate required image/audio assets and safe paths, store immutable media, validate the new manifest, atomically save it, and retain original JSON inside each imported board. A failure exposes an error and never replaces the original library with an empty board. Partial media writes are harmless unreferenced blobs; the manifest is the publication boundary.

A first-run migration gate is implemented for the two production identities, before normal editing is available, only when no new library manifest exists. Development identities use the explicit import UI. The identity gate and repeatability are tested against the real legacy fixture. Do not assume merely changing the bundle ID is a finished upgrade. Run the real old-version → new-version sequence on fixture installations of both identities and compare counts, ordering, covers, long English/Spanish labels, audio playback, all formatting and print dimensions. Preserve original folders for recovery until an independently tested backup exists.

`library.json` is schema version 1. The prior valid manifest is retained as `library.previous.json`. Failed-load UI offers Retry and Restore previous save, and recovery keeps the unreadable manifest under a unique recovery filename. Normal editing never proceeds after a failed load. Board deletion is a reversible flag; media is immutable and not automatically garbage-collected. Complete backups include deleted boards and their media.

Legacy `repeatSinglePhoto` is session-only in PageLayoutState, not encoded by PECSRepo. The new print setting persists it going forward. Legacy raw JSON is retained for any metadata that has no current UI control; unknown schema versions are rejected instead of guessed. Imported legacy card order is taken directly from `photos.photoItems`. Legacy boards are imported in name order with the localized New Board first, matching the audited RepoFactory sorting rule; no undocumented filesystem order is claimed as user intent.
